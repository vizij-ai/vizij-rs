---
"@vizij/runtime": major
---

A page drives its Vizijs through the handle `mount` resolves to, by instance — an id of the page's own, never rewritten, which every call about a face and every event from it carries — and hears from them through one pushed event stream, in the shape `@semio/scene` gives robots.

- `vizijs.load(instance, glb, options)` loads a Vizij into the instance and resolves to its `Runtime` once the face has loaded whole; under an instance showing a face it replaces it, the face showing drawing until the new one is ready. It rejects, keeping what the instance showed, when the GLB does not read or build, its scene fails to load or lacks a node its RobotData names, or a later load into the instance, or its unload, comes first; the device of a load that rejects is disposed by the package. `options.key` names the content: a load of the key an instance shows, with none loading, resolves to the device showing it, and a load of the key it is loading joins that load. `vizijs.unload(instance)` takes the face down and rejects anything loading into it.
- `vizijs.onEvent(handler)` hears every event, each naming its `instance`: `loaded` (`key`, `elements: { id, name }[]`), `loadFailed` (`key`, `error`), `ready` (`drawn`, false when readiness gave up waiting to see the face drawn), `pick` (`element`, `null` for a miss) and `safeArea` (`area`, `null` once it has none). An instance's `loaded` and `loadFailed` arrive in the order its loads were asked for. `vizijs.faces`, `vizijs.loading` and `vizijs.safeAreas` hold the current state, set before a handler hears the event that changed it. Events from before a handler is set are not replayed, but a handler newly set hears the `overlay` and every face's `safeArea` as they stand in the next frame.
- `vizijs.place(instance, rect | "fill")` and `vizijs.placeIn(instance, element)` say where a face draws on the canvas; `vizijs.setView`, `vizijs.setSelection` take the instance.
- `vizijs.setValue(instance, element, value, feature)` writes one number or three to a feature of an element in place. The feature is required: a face's animatables are its device's outputs, written through its `Runtime`.
- `vizijs.control(command)` adds, removes, shows, moves and changes transform controls on faces, by the driver's key, in the command shape `@semio/scene` takes: a control on a face names its instance, and a goal names the face it is used through as its `view`, which the `ControlTarget` type requires; `control` throws for a goal naming none, since every face has a camera of its own. A drag moves nothing; it is heard as a `control` event (`key`, `phase`, `pose`, `scale`), and a press with another button as `controlPress`. An `overlay` event says where elements and controls stand on the canvas and which control the pointer has, each frame it changes. A control on a face is 80 px on screen unless the command gives it a `size` (`{ pixels }` or `{ metres }`), on its add or a `configure`. A transform control's arrows stay on each axis's positive side unless it is given `faceViewer`, which turns them toward the camera. A joint control throws: a face has no joints. The controls on a face, and the goals used through it, go when it is unloaded or reloaded, as a robot's do on a swap; the driver adds them again to the new face. A control or goal sent while a load into its face is under way waits for the load's answer and lands on the face showing after it: the new face, or the one kept when the load fails. The command, event and overlay types are exported.
- `Runtime.instance` names the instance a device's face was loaded into.
- **Breaking:** `loadVizij`, `unloadVizij`, `placeVizij`, `placeVizijIn`, `fillCanvas`, `setView`, `setSelection`, `setStaticFeature`, `safeArea`, `ready`, `whenReady`, `drainPicks`, the `Pick` type and `Runtime.vizijId` are gone: their work is the handle's and the event stream's. `mount` resolves to the handle rather than to nothing.
